Here “championship” means preparation for contests such as a continental championship. The exact qualification structure depends on the region and season. All preliminary and regional skills remain active; this stage is primarily about combining tools and improving proof quality.

Suggested pace: several months, with one full team set most weeks when feasible. Work through C01-C09 according to prerequisites, then C10-C11 around the team's weaknesses. Alternate advanced modules with easy/medium problems from real sets.

Team coverage: everyone should recognize the main reductions; initially assign deeper implementation ownership of trees/data structures, graphs/flows, and mathematics/geometry/strings. Rotate ownership so no essential routine has only one person who understands it.

Exit evidence: four unseen championship virtuals with detailed upsolving; at least two members able to review each essential template; written proofs of every optimization condition; stress tests for the library that will be brought to contests.

Past-paper bridge: Europe Championship 2025 A, F, B, and G; Asia West 2025 as an intact local-relevance set. Read Past papers for verification levels and spoiler handling.

C01 · Heavy-light decomposition and small-to-large

Prerequisites: R04,R05,R07.

Learn: Heavy paths; path aggregates and updates; direction-sensitive merges; DSU-on-tree/sack; small-to-large amortization.

Mastery check: Prove a path crosses O(log n) light edges and maintain subtree color statistics.

Watch for: Confusing DSU-on-tree with union-find; reversing a noncommutative path aggregate.

Study: Heavy-light decomposition; KACTL reference and testing guidance.

Understand the idea

Heavy-light decomposition converts a tree path into a small number of contiguous chain intervals. Select a largest-subtree child as heavy; every light edge reduces the remaining subtree scale sufficiently to give O(log n) chain changes. A segment tree then usually gives O(log^2 n) path queries. Small-to-large merging instead reuses the largest child's container and moves smaller containers into it. DSU-on-tree is related bookkeeping for subtree statistics, distinct from connectivity DSU.

Worked example / reasoning

For a noncommutative aggregate such as string concatenation, collecting chain intervals in arbitrary order reverses parts of a path. Maintain separate accumulators for the two endpoints and reverse the appropriate segment direction. For small-to-large sets, each moved element joins a container at least twice as large, bounding its moves by O(log n).

Learning sequence

  1. Implement path maximum before attempting direction-sensitive path aggregates.
  2. Prove the doubling argument for container merging.
  3. Compare subtree color counts from a simple traversal with a sack or merging solution.

C02 · Centroid decomposition and tree counting

Prerequisites: R04,R05.

Learn: Centroid balance; nearest marked vertex; distance histograms; subtract within-child pairs; bitmask parity on paths.

Mastery check: Prove logarithmic decomposition depth and count paths exactly once by their first separating centroid.

Watch for: Including a subtree's pairs before excluding its internal pairs; stale state across decomposition levels.

Study: Centroid decomposition.

Understand the idea

A centroid splits a tree into components of at most half its size, yielding a logarithmic-depth decomposition. A path is counted at the first decomposition level where its endpoints lie in different centroid branches, or one endpoint is the centroid. This ownership rule prevents duplicate counting. Distance-to-marked queries can keep a best value at every centroid ancestor. Histogram methods must exclude pairs lying entirely within one child branch because those belong to a deeper recursive component.

Worked example / reasoning

To count paths of length K through centroid c, begin with a frequency table containing distance zero for c. For each child branch, query complementary distances K-d against previously processed branches, then insert that branch's distances. Querying before inserting prevents counting two endpoints from the same branch at this level.

Learning sequence

  1. Find a centroid using subtree sizes and verify the balance condition.
  2. Count fixed-length paths and compare with all-pairs distances on small trees.
  3. Implement mark/query operations and explain which centroid ancestor witnesses an optimal path.

C03 · Persistence, rollback, and parallel binary search

Prerequisites: R06,R08,R17.

Learn: Persistent segment trees; version roots; rollback DSU without path compression; segment tree over time; parallel binary search; Kruskal reconstruction trees.

Mastery check: Describe the historical version or active time interval represented by every structure.

Watch for: Rollback with unlogged path compression; treating persistence as a copy of the entire array.

Study: Deleting from a data structure in O(T(n) log n); Segment Tree.

Understand the idea

Persistence preserves previous versions by copying only changed nodes. Rollback records reversible mutations and returns a structure to an earlier snapshot; standard path compression is usually omitted from rollback DSU. A segment tree over time places each active interval into nodes where its contribution is valid. Parallel binary search groups many monotone answer searches so they can share a sweep. A Kruskal reconstruction tree records component merges as weighted ancestors for later threshold queries.

Worked example / reasoning

A persistent point update in a segment tree creates O(log n) nodes and shares untouched children with the old root. For an edge active during [l,r), add it to the corresponding time-tree nodes. During DFS, snapshot the DSU, apply that node's edges, answer leaf queries, and roll back before visiting siblings.

Learning sequence

  1. Estimate node-pool memory before constructing persistent versions.
  2. Stress-test snapshot/rollback sequences, including redundant unions.
  3. Derive active intervals and ensure insertion and deletion timestamps match query semantics.

C04 · DP optimization

Prerequisites: R02,R06,R18.

Learn: Convex hull trick/Li Chao; divide-and-conquer DP; Monge and monotone optima; Knuth optimization; prefix-sum acceleration.

Mastery check: Prove the optimization's hypothesis before using it and compare against cubic/quadratic brute force.

Watch for: Applying Knuth or divide-and-conquer optimization solely because the recurrence looks familiar.

Study: Convex hull trick and Li Chao tree; Divide and Conquer DP; Knuth's Optimization.

Understand the idea

Optimizing DP starts with a correct slow recurrence. Algebra may turn transitions into line queries for a convex hull trick or Li Chao tree. Divide-and-conquer optimization needs monotone optimal split positions; Knuth optimization needs a stronger interval structure with bounded neighboring optima. Monge or quadrangle conditions must be established for the actual cost function. Prefix sums can also remove repeated work without requiring a sophisticated theorem.

Worked example / reasoning

If dp[i] = min over j<i of dp[j] + (x[i]-x[j])^2, expand the square to x[i]^2 + min((-2*x[j])*x[i] + dp[j]+x[j]^2). Each earlier j contributes a line. Monotone slopes and queries permit simpler hulls; arbitrary order may require Li Chao or a different balanced structure.

Learning sequence

  1. Derive and implement the quadratic recurrence as a reference.
  2. State the theorem assumptions for each optimization and test argmin behavior on small cases.
  3. Handle equal slopes, tie-breaking, coordinate bounds, and wide intermediate products explicitly.

Watch, read, and go deeper

C05 · Digit, profile, and subset-transform DP

Prerequisites: R03,R14.

Learn: Digit DP with tight/started flags; broken-profile tiling; SOS DP; subset convolution awareness; memory compression.

Mastery check: Distinguish state encoding from transition enumeration and account for leading zeros.

Watch for: Counting zero twice; incompatible mask conventions between adjacent columns; O(3^n) work hidden inside masks.

Study: Dynamic Programming on Broken Profile. Problem "Parquet"; Enumerating submasks of a bitmask.

Understand the idea

Digit DP processes a bound from most significant digit to least, retaining only properties needed by the remaining suffix. Tight records whether the prefix still equals the bound; started distinguishes leading zero padding from actual digits. Profile DP stores the frontier between processed and unprocessed cells of a narrow grid. SOS transforms aggregate information over all submasks by processing one bit at a time. These are different state-compression techniques, with different correctness arguments and state counts.

Worked example / reasoning

To count numbers in [L,R] whose digit sum is divisible by d, compute F(R)-F(L-1) with state (position,remainder,tight). Add started if the property distinguishes leading zeroes or excludes zero. For domino tilings, a profile mask can describe occupied cells in the next column; transitions must fill every current-column hole exactly once.

Learning sequence

  1. Implement a digit DP and compare every bound up to a small limit with enumeration.
  2. Draw profile transitions for widths two and three.
  3. Derive the SOS update and compare transformed sums with explicit submask enumeration.

Watch, read, and go deeper

C06 · Automata and suffix structures

Prerequisites: R15.

Learn: Aho-Corasick failure links and output propagation; suffix array/LCP; suffix automaton states and occurrence counts; Manacher odd/even radii.

Mastery check: Explain the substring interval represented by a suffix-automaton state and verify overlapping pattern matches.

Watch for: Missing failure-link output propagation; using distinct-substring formulas with occurrence counts.

Study: Aho-Corasick algorithm; Suffix Array; Suffix Automaton; Manacher's Algorithm - Finding all sub-palindromes in O(N).

Understand the idea

Automata and suffix structures summarize many overlapping string queries. Aho-Corasick extends a trie with failure links so scanning one text can report many patterns. Suffix arrays order suffixes and use LCP values to express repeated-substring structure. A suffix automaton groups substrings with the same end-position behavior; occurrence counts propagate in decreasing state length. Manacher handles palindromes using mirrored radius information and separate odd/even conventions.

Worked example / reasoning

When pattern he is a suffix of pattern she, reaching the state for she must also account for he through failure/output propagation. In a suffix automaton, a state with length len[v] and suffix link p represents substring lengths len[p]+1 through len[v]; their count is len[v]-len[p]. Clone states need careful initialization when counting occurrences.

Learning sequence

  1. Verify every reported pattern occurrence against direct matching.
  2. Use suffix-array LCPs to count distinct substrings.
  3. Compare Manacher radii and suffix-automaton occurrence counts with brute force on repetitive strings.

Watch, read, and go deeper

Suffix array and LCP construction; the linked automata and palindrome references complete the module's other structures.

C07 · Min-cost flow, assignment, and constrained flow

Prerequisites: R13,R09.

Learn: Successive shortest augmenting paths; potentials; negative residual costs; Hungarian assignment; lower-bound circulation; min-cut reductions.

Mastery check: Explain feasible initial potentials and reconstruct a min-cost assignment or shipment.

Watch for: Using Dijkstra on negative reduced costs; forgetting balance constraints when adding lower bounds.

Study: Minimum-cost flow; Hungarian Algorithm; Flows with demands.

Understand the idea

Min-cost flow augments along a cheapest residual path, including reverse edges that can cancel earlier assignments. Potentials reweight edges so Dijkstra can be used once feasible reduced costs are established. Negative initial costs require an appropriate initialization or a justified special structure. Hungarian assignment is a specialized alternative for dense assignment matrices. Lower bounds on flow become balance demands and an auxiliary feasibility problem; model the original objective separately from feasibility.

Worked example / reasoning

For an edge u->v with mandatory lower flow l, reserve l units, reduce its capacity by l, and update the two vertex balances consistently. A super-source and super-sink route the resulting imbalances. In assignment, a negative-cost reverse residual edge represents undoing a previous worker-job choice, not an illegal negative original assignment.

Learning sequence

  1. Write the conservation and cost equations for a tiny assignment instance.
  2. Check potentials and reduced costs after every augmentation on a small graph.
  3. Validate lower-bound feasibility and recover original edge flows by restoring the reserved amounts.

Watch, read, and go deeper

The videos establish residual-flow and matching foundations; the handout develops costs and the dedicated references cover demands and assignment.

C08 · Advanced number theory and polynomial tools

Prerequisites: R14.

Learn: Mobius inversion; divisor transforms; Euler phi; FFT/NTT; convolution versus correlation; generating functions; polynomial degree and coefficient bounds.

Mastery check: Derive which coefficients encode the answer and choose a transform modulus/length that supports them.

Watch for: Confusing cyclic with ordinary convolution; trusting floating FFT beyond its safe precision range.

Study: Fast Fourier transform; Operations on polynomials and series.

Understand the idea

Divisor transforms reorganize sums over divisibility, and Mobius inversion reverses a divisor-sum relation. Euler's totient counts residues coprime to a modulus and connects arithmetic structure to exponent reduction under suitable assumptions. Convolution encodes pairwise index sums as polynomial coefficients. FFT uses complex arithmetic; NTT uses roots of unity in a finite field and imposes transform-length restrictions. Generating functions turn counting recurrences into coefficient operations, but the algebra must preserve truncation and modulus conditions.

Worked example / reasoning

If A[x] and B[y] count two collections, the coefficient of z^s in A(z)B(z) counts pairs with x+y=s. Correlation instead compares shifts and generally requires reversing one sequence. Before NTT, ensure the output degree fits the padded length and the chosen modulus supports that length. Multiple moduli may be needed to recover large integer coefficients.

Learning sequence

  1. Derive one divisor-sum identity and invert it on small integers.
  2. Compare convolution with a quadratic multiplication reference.
  3. Record coefficient bounds, transform length, available roots, and whether exact reconstruction is necessary.

Watch, read, and go deeper

Polynomial multiplication and transform derivation; divisor transforms require separate number-theory reading.

C09 · Probability processes and algebra

Prerequisites: R18,R19.

Learn: Absorbing Markov chains; expected hitting times; self-loops; linear systems over reals and finite fields; XOR basis; transition powers.

Mastery check: Derive E=1+PE for transient states and justify finite expectation before solving.

Watch for: Dividing by zero for an absorbing class; treating singular equations as a unique solution.

Study: Gauss & System of Linear Equations; Handbook, chapters 24.

Understand the idea

Expected hitting times are solved by conditioning on the next step, often producing a linear system rather than an acyclic DP. Self-loops move part of the unknown back onto the left-hand side. Absorbing behavior and reachability matter: some states have infinite expected completion time. Finite-field linear algebra has exact modular semantics, while real-valued systems require numerical care. An XOR basis is Gaussian elimination over GF(2), representing the span of bit vectors.

Worked example / reasoning

If a state finishes with probability p and returns to itself otherwise, E = 1 + (1-p)E, so E = 1/p for p>0. When p=0, the expectation is infinite and division is invalid. For an XOR basis, insert a vector by repeatedly canceling its highest set bit; a zero remainder means linear dependence.

Learning sequence

  1. Build equations from a small absorbing process and check them by substitution.
  2. Identify states that cannot reach termination before solving expectations.
  3. Implement XOR-basis insertion, membership, rank, and maximum obtainable XOR.

Watch, read, and go deeper

Expectation, linear independence, and bases; use elimination and GF(2) references to connect these foundations to cyclic processes and XOR spans.

C10 · Geometric modeling and transformations

Prerequisites: R16,R18.

Learn: Angular sweeps; line/circle intersections; affine transformations; rotating calipers; convex distance; robust degeneracy handling.

Mastery check: State a consistent boundary convention and test tangent, parallel, coincident, and zero-length cases.

Watch for: Assuming general position when the statement permits collinearity or tangency.

Study: Circle-Circle Intersection; Check if points belong to the convex polygon in O(log N).

Understand the idea

Geometric modeling often becomes manageable after translating or rotating coordinates, sweeping by angle, or exploiting convexity. Affine transformations preserve lines and incidence but generally change lengths and angles. Circle intersections need explicit classifications for disjoint, tangent, coincident, and two-point cases. Convex-distance and rotating-calipers arguments rely on monotone movement. Robust code should make degeneracy decisions at the predicate level rather than sprinkling unrelated epsilons throughout the algorithm.

Worked example / reasoning

For Manhattan distance in two dimensions, use u=x+y and v=x-y; then |dx|+|dy| equals max(|du|,|dv|). This can turn diamond-shaped constraints into axis-aligned boxes. The inverse transform divides by two, so integer-coordinate parity must be preserved when reconstructing a point.

Learning sequence

  1. Derive one coordinate transformation and prove the equivalence of feasible regions.
  2. Enumerate every possible line/circle intersection classification.
  3. Test nearly tangent circles, repeated points, parallel lines, and convex polygons with collinear edges.

Watch, read, and go deeper

Convex-hull and coordinate prerequisites; the slides and circle references extend these to sweeps and geometric modeling.

C11 · Amortization and combined structures

Prerequisites: R07,R09,C01.

Learn: Segment-tree graph compression; modulo-update amortization; bitsets; bounded-value tricks; offline/online tradeoffs.

Mastery check: Give a potential-function or size-halving argument for the total expensive work.

Watch for: Claiming a fast average case without a worst-case or randomized justification.

Study: Segment Tree; KACTL reference and testing guidance.

Understand the idea

Combined structures compress a large transition system or exploit limited total change. Segment-tree graph gadgets represent edges from one vertex to an interval, or an interval to one vertex, with only logarithmically many connections per operation. Bitsets perform many boolean transitions per machine word. Amortized bounds charge expensive updates to a quantity that decreases, rather than claiming each operation is individually cheap. Offline processing may simplify a problem enough to remove an advanced online structure.

Worked example / reasoning

For nonnegative values and modulo updates by positive x, a value changes only when a>=x. Whenever it changes, a mod x < a/2: if x<=a/2 the remainder is below x; otherwise the new value is a-x<a/2. A segment maximum lets an update skip nodes already below x. Point assignments can replenish the potential and must be included in the total bound.

Learning sequence

  1. Prove a potential or doubling argument for the actual update sequence.
  2. Build separate inward and outward segment-tree graph gadgets and validate reachability.
  3. Compare bitset and scalar DP on dense small instances before optimizing memory layout.

Watch, read, and go deeper

Aggregate and potential arguments; apply the proof method to combined structures rather than assuming per-operation bounds.

C12 · Championship contest integration

Prerequisites: R20,C01-C11.

Learn: Multi-step reductions; proof-first discussion; deliberate partial progress in training; adversarial testing; responsibility handoffs.

Mastery check: Virtual at least four championship sets; fully review two difficult reductions per set and reimplement key templates.

Watch for: Trying to learn every specialist algorithm before learning to combine the regional core.

Study: KACTL reference and testing guidance.

Understand the idea

Advanced contest performance depends on finding a chain of valid reductions and communicating where each one is justified. Separate structural claims from implementation claims so a teammate can challenge the model before a large template is written. Use training partial solutions to isolate bottlenecks, but remember that ordinary ICPC judging generally requires a fully accepted solution to score a problem. A handoff should include the state definition, invariants, bounds, counterexamples already tested, and unresolved questions.

Worked example / reasoning

Suppose a problem appears to require flow plus binary search. First prove the threshold predicate is monotone, then prove feasible flows correspond exactly to valid original solutions, and only then optimize the implementation. A fast max-flow routine cannot compensate for a reduction allowing an item to be used twice.

Learning sequence

  1. Present one missed problem as a sequence of equivalence-preserving reductions.
  2. Run adversarial tests written by the teammate who did not implement the solution.
  3. Record whether time was lost to modeling, proof, coding, testing, or communication.

Watch, read, and go deeper

A challenge-solving discussion and examples of reductions; use them to practice communicating proof obligations.
