This is the main starting track. If you already solve routine implementation problems comfortably, use P01-P05 as a diagnostic and spend your time on P06-P15. Do not skip them merely because their names look familiar. These are preparation priorities, not a claim that preliminary contests contain only these topics.

Suggested pace: 8-12 weeks at roughly 8-12 focused hours per week, adjusted to your current ability. A newcomer may need longer. Each week, learn one or two related modules, solve their starter/core exercises, and spend a session on mixed untagged problems. Start timed practice before finishing the syllabus.

First pass: P01-P08, then P09-P13. Add P14-P15 while starting full-set practice in P16. Stretch problems are optional on the first pass. For a strong preliminary contest, start R01, R02, R06, R08, and R09 as soon as their prerequisites are ready.

Exit evidence: explain and implement the basic tools without copying; solve unfamiliar combinations under time pressure; complete three unseen preliminary-style sets and upsolve reachable misses. A solve count is meaningful only relative to that specific set and its standings. This roadmap does not promise qualification at any rating or solve count.

P01 · Language, complexity, and arithmetic

Prerequisites: None.

Learn: C++17/20 syntax and STL; input until EOF and multiple cases; integer division; 64-bit arithmetic; O(1), logarithmic, linear, n log n, quadratic and exponential bounds; memory estimates.

Mastery check: Derive the largest intermediate value and operation count before coding; compile and run from a terminal.

Watch for: Promoting after an overflowing multiplication; stale state between cases; assuming every judge supports the same compiler.

Study: Handbook, chapters 1-2.

Understand the idea

An algorithm must fit both the mathematical constraints and the machine representation. Translate the largest input into a bound on work, memory, and intermediate values before choosing a container or loop. Separate worst-case complexity from an estimate of runtime: an O(n) algorithm can still allocate too much memory. In C++, expressions are evaluated using their operand types, so assigning a product to long long does not repair an earlier int overflow. Learn vectors, pairs, iterators, references, and the standard algorithms you will use repeatedly.

Worked example / reasoning

For n = 200000, checking all pairs means about 20 billion comparisons; sorting needs roughly n log2(n) comparisons. Multiplying two values up to 10^9 requires widening an operand before multiplication. For nonnegative a and positive b, a / b + (a % b != 0) computes ceiling division without adding b - 1.

Learning sequence

  1. Compile a minimal multi-case template and an EOF-based reader.
  2. Estimate storage for an n by n table and compare it with an adjacency list.
  3. Test division and remainders on negative values; distinguish language rules from mathematical floor.

Watch, read, and go deeper

Contest setup and complexity; supplement the examples with your compiler's C++ documentation.

P02 · Simulation and careful implementation

Prerequisites: P01.

Learn: Translate rules into explicit state transitions; arrays, grids, indices, simultaneous versus sequential updates; counting and running extrema.

Mastery check: Explain the state after each step and test smallest inputs, ties, and repeated values.

Watch for: Changing a state in place when the problem requires all changes to happen simultaneously.

Study: Handbook, chapters 1,5.

Understand the idea

Simulation starts by defining exactly what the state contains and when an update becomes visible. Write the transition for one event, then identify what must be remembered between events. A useful loop invariant describes the state after the first k events. For a grid process, explicitly decide whether neighbors are read from the old grid or the changing grid. Prefer a simple direct simulation until the input bounds demonstrate that acceleration is necessary.

Worked example / reasoning

If every adjacent BG pair swaps simultaneously, a left-to-right in-place pass must skip the position just moved into. Otherwise one child can move several places in a single round. A second buffer provides a general alternative when updates overlap more extensively.

Learning sequence

  1. Trace three events by hand and record the state after each.
  2. Implement a direct reference simulator before optimizing repeated operations.
  3. Build cases with no changes, all changes, equal timestamps, and multiple test cases.

P03 · Elementary strings and parsing

Prerequisites: P02.

Learn: Character classification; case conversion; lexicographic comparison; runs; palindrome checks; subsequences versus substrings; token versus whole-line input.

Mastery check: Implement a linear subsequence scan and explain why skipped characters cannot help later.

Watch for: Confusing contiguous substrings with subsequences; getline after token input; empty and repeated characters.

Study: Handbook, chapters 26.

Understand the idea

Treat a string problem as a question about positions and relationships before choosing a string algorithm. A substring occupies a contiguous interval; a subsequence preserves order while allowing gaps. Runs can be processed with a current character and length. Lexicographic order is determined by the first unequal character, with a shorter prefix ordered first. Parsing requires an explicit input grammar: whitespace-separated tokens, complete lines, delimiters, and empty fields need different handling.

Worked example / reasoning

To test whether abc is a subsequence of axbyc, keep the index of the next unmatched target character and advance it only on a match. Choosing the earliest possible matching position leaves at least as much remaining text as any later choice. This gives a linear scan without recursion.

Learning sequence

  1. Implement reversal, palindrome checking, run counting, and subsequence testing.
  2. Read a line containing spaces after a numeric input and handle the leftover newline.
  3. Explain whether empty strings, punctuation, and case differences affect your specification.

Watch, read, and go deeper

Optional later reading on string algorithms; first finish the elementary scans above. The video covers array storage rather than parsing.

P04 · Sorting, comparators, and order

Prerequisites: P02.

Learn: Sort numbers and pairs; stable ordering; tie handling; distinct values; coordinate compression as an introduction.

Mastery check: Write a comparator that is a strict weak ordering and identify what sorting makes adjacent.

Watch for: Using <= in a comparator; forgetting the secondary key; losing original indices.

Study: Handbook, chapters 3.

Understand the idea

Sorting reveals structure by placing comparable objects next to each other. It can turn duplicate detection, closest-value searches, interval processing, and rank queries into simple scans. Choose the key before writing the comparator, including the direction of every tie-break. A valid comparator must reject comp(x,x) and remain transitive. Coordinate compression replaces values by sorted distinct ranks: it preserves relative order and equality, but does not preserve numerical distances.

Worked example / reasoning

For records (score, penalty), rank by descending score and then ascending penalty. Two records with identical keys belong to the same rank group even if their original indices differ. If coordinates 10 and 1000 compress to consecutive ranks, their geometric gap is still 990, not one.

Learning sequence

  1. Express a multi-key order as a tuple or an explicit strict comparator.
  2. Sort while retaining original indices, then restore answer order.
  3. Implement compression with sort, unique, and lower_bound; verify duplicates share a rank.

Watch, read, and go deeper

P05 · Frequency counting, sets, and maps

Prerequisites: P03,P04.

Learn: Frequency arrays; map/set/multiset; hash maps; duplicate handling; algebraically transform a pair condition into equal keys.

Mastery check: Turn a quadratic pair count into a linear or n log n frequency computation.

Watch for: Erasing all copies from a multiset; counting self-pairs; treating a hash table as a string-hashing algorithm.

Study: Handbook, chapters 4.

Understand the idea

A frequency table groups objects by the information relevant to the answer. Use an array for a small dense key range, a balanced map for ordered operations, and a hash table for expected fast lookup when order is irrelevant. A set records presence; a multiset retains multiplicity. Before storing a complicated object, try rearranging the condition into equal keys or complementary keys. Decide whether a query counts previous elements or all elements, since that determines self-pair handling.

Worked example / reasoning

The condition a[j] - a[i] = j - i is equivalent to a[j] - j = a[i] - i. Scanning left to right, add the number of previous occurrences of a[i] - i, then increment its frequency. A group of size k contributes k(k-1)/2 unordered pairs.

Learning sequence

  1. Solve one pair-counting problem with a quadratic baseline and then a frequency scan.
  2. Compare erase(value) with erase(iterator) on a multiset containing duplicates.
  3. Test a single huge frequency and use a wide type for the pair count.

Watch, read, and go deeper

Hashing assumptions and collision behavior; compare these with the ordered-container tradeoffs above.

P06 · Prefix sums and difference arrays

Prerequisites: P02.

Learn: Half-open and inclusive ranges; prefix sums; prefix counts; difference updates; 2D prefix sums; prefix XOR.

Mastery check: Derive a range formula from the definition; explain why two prefix passes solve offline interval coverage.

Watch for: Subtracting the wrong endpoint; indexing r+1 outside storage; overflow in cumulative sums.

Study: Handbook, chapters 9.

Understand the idea

Prefix aggregates exchange preprocessing for cheap static interval queries. With p[0] = 0 and p[i+1] = p[i] + a[i], the sum on [l,r) is p[r] - p[l]. A difference array performs the inverse viewpoint: record changes at interval boundaries, then accumulate once to recover values. For offline updates followed by queries, build coverage first and a second prefix table afterward. Two-dimensional prefixes use inclusion-exclusion to remove the overlap subtracted twice.

Worked example / reasoning

Adding 5 to [2,5) records d[2] += 5 and d[5] -= 5. One prefix pass applies the update to indices 2, 3, and 4. For [3,1,4,2], p = [0,3,4,8,10], so the sum on [1,3) is 8 - 3 = 5.

Learning sequence

  1. Derive the interval formula from your chosen indexing convention.
  2. Implement offline range additions and compare the resulting array with direct updates.
  3. Extend to a rectangle query and explicitly draw the four prefix rectangles.

Watch, read, and go deeper

Range-query context in the slides; the dedicated video explains prefix sums. Derive difference-array formulas separately.

P07 · Two pointers and sliding windows

Prerequisites: P04,P06.

Learn: Opposite-end scans; positive-sum windows; distinct-element windows; maintaining counts; amortized linear movement.

Mastery check: State precisely why moving one endpoint is safe and why each endpoint advances O(n) times.

Watch for: Using a positive-sum window when negative values destroy monotonicity.

Study: Handbook, chapters 8.

Understand the idea

Two pointers are justified by a monotone elimination rule, not simply by using two indices. On sorted data, an endpoint can discard many impossible pairs at once. In a sliding window, maintain an invariant about the current interval and adjust its left boundary when extending the right boundary breaks it. The nested loops can still be linear because each endpoint advances at most n times. Distinguish maintaining a sum from maintaining a frequency map or an extremum.

Worked example / reasoning

For positive values and a sum limit S, extending the right endpoint cannot decrease the sum, and removing the leftmost value cannot increase it. These facts justify shrinking an invalid window. With negative values, an invalid partial window may become valid after extension, so the same proof fails.

Learning sequence

  1. Write the window invariant and the exact condition for shrinking.
  2. Trace opposite-end pair search on a sorted array with duplicates.
  3. Solve a distinct-element window and verify that deleting one occurrence does not erase all copies.

Watch, read, and go deeper

P08 · Binary search and answer search

Prerequisites: P04,P06.

Learn: lower_bound/upper_bound; first true/last false; prefix search; monotone feasibility; integer and real domains.

Mastery check: Give an invariant, a feasible bound, and a monotonicity proof before implementing answer search.

Watch for: Off-by-one errors, unsafe midpoint arithmetic, or binary search on a nonmonotone predicate.

Study: Binary Search.

Understand the idea

Binary search locates a boundary in an ordered domain. In answer search, the array is implicit: a feasibility function supplies false/true values. First prove that feasibility changes direction at most once, then choose bounds that contain the boundary. A half-open search with a sentinel avoids treating every loop as a new off-by-one puzzle. Include the cost of one predicate evaluation in the final complexity. For real-valued answers, relate the iteration count to interval width and required precision.

Worked example / reasoning

If machines take 2 and 3 time units per item, production by time T is floor(T/2) + floor(T/3). Producing four items is impossible at T = 5 and possible at T = 6. The predicate is monotone because increasing time never removes produced items. Cap the running count once it reaches the target to avoid overflow.

Learning sequence

  1. Implement first-true search and test all-false and all-true domains.
  2. Prove a feasible upper bound instead of choosing an unexplained constant.
  3. Compare lower_bound and upper_bound on repeated values and missing keys.

Watch, read, and go deeper

Use the dedicated boundary-search video first; the slides supplement complexity and implementation checks.

P09 · Enumeration, recursion, and bits

Prerequisites: P01.

Learn: Subsets and permutations; recursion and backtracking; pruning with proof; bit tests, popcount, XOR; exhaustive small-instance solvers.

Mastery check: Count the search space and build a brute-force reference for a later optimized solution.

Watch for: Pruning valid branches; signed shifts; enumerating 2^n when n is too large.

Study: Handbook, chapters 5; Bit manipulation.

Understand the idea

Enumeration is both a complete solution for small inputs and a tool for checking more sophisticated algorithms. Choose a representation that makes every candidate appear exactly once: subset masks, increasing combinations, lexicographic permutations, or a recursion tree. Estimate the number of states and the work per state separately. Backtracking must restore modified state before trying the next branch. Pruning is valid only when no completion of the current partial choice can succeed or improve the answer.

Worked example / reasoning

Twenty items have 2^20 subsets, about one million; forty items have about one trillion. For a queen placement search, occupied columns and diagonals can reject a branch immediately. A bitmask stores a set compactly, but shifting by an invalid width or into a signed overflow is not a substitute for a mathematical bound.

Learning sequence

  1. Implement subsets recursively and with masks; compare their outputs.
  2. Write a brute-force solver that also returns a witness.
  3. Document why every pruning condition is sound and test it against an unpruned version.

Watch, read, and go deeper

P10 · Greedy proofs, invariants, and construction

Prerequisites: P04,P09.

Learn: Exchange arguments; staying ahead; parity and conservation; feasibility then construction; extremal choices; counterexample hunting.

Mastery check: Explain why a local choice preserves an optimum, or exhibit a counterexample to an attractive wrong rule.

Watch for: Calling a heuristic greedy; ignoring impossible cases; proving necessity without sufficiency.

Study: Handbook, chapters 6.

Understand the idea

A greedy algorithm commits to a local decision without revisiting it. Its central task is a proof that an optimum can be modified to include that decision. Exchange arguments replace an alleged optimum's first conflicting choice; staying-ahead proofs compare partial solutions. In constructive tasks, identify necessary constraints such as parity or total sum, then prove they are sufficient by building a valid object. Invariants describe what operations preserve, while extremal arguments focus on a smallest or largest object.

Worked example / reasoning

For maximum-cardinality nonoverlapping interval selection, choose the compatible interval finishing earliest. Replacing the first interval of any optimum with this one cannot block its later intervals. Sorting by shortest duration has no corresponding guarantee and admits counterexamples. Weighted interval selection requires a different model, usually DP.

Learning sequence

  1. Write a two-paragraph exchange proof before implementing a greedy rule.
  2. Use exhaustive small inputs to find counterexamples to alternative rules.
  3. For a construction, verify feasibility, termination, and every output constraint separately.

Watch, read, and go deeper

Interval scheduling, greedy reasoning, and correctness proofs; compare the proof patterns with your construction.

P11 · Elementary number theory and counting

Prerequisites: P01,P09.

Learn: GCD/LCM; sieve; divisors and prime factorization; modular arithmetic; fast exponentiation; basic permutations/combinations; pigeonhole arguments.

Mastery check: Implement a sieve and modular power; prove a divisor characterization and bound products safely.

Watch for: Treating 1 as prime; multiplying before dividing for LCM; assuming modular division always exists.

Study: Euclidean algorithm for computing the greatest common divisor; Sieve of Eratosthenes; Binary Exponentiation.

Understand the idea

Number theory begins with divisibility rather than formulas to memorize. Euclid's algorithm repeatedly replaces a pair by a smaller equivalent gcd problem. A sieve amortizes primality or divisor information across a bounded range. Factorization converts divisor questions into choices of prime exponents. Modular arithmetic permits addition and multiplication after reduction, but division requires an invertible denominator. Counting tasks also need clarity about order, repetition, and whether objects are distinguishable.

Worked example / reasoning

If n = p^2 for prime p, its divisors are exactly 1, p, p^2; conversely, three divisors force that structure. For lcm(a,b), compute a/gcd(a,b) before multiplying by b and still check the final bound. Binary exponentiation processes exponent bits, reducing O(k) repeated multiplication to O(log k).

Learning sequence

  1. Implement gcd, a sieve, factorization, and modular exponentiation independently.
  2. Derive divisor count as the product of exponent-plus-one terms.
  3. Check whether a modular inverse exists using gcd before applying a division rule.

Watch, read, and go deeper

P12 · Basic dynamic programming

Prerequisites: P06,P09.

Learn: State, transition, base case, order and answer; memoization versus iteration; min/max/count DP; coin change; reconstruction.

Mastery check: Explain why each state contains enough information and why every solution is counted exactly as intended.

Watch for: Accidental unbounded reuse in 0/1 knapsack; unreachable states treated as zero; permutations versus combinations.

Study: Introduction to Dynamic Programming; Knapsack Problem.

Understand the idea

Dynamic programming merges partial solutions that have the same relevant future. Define the meaning of a state in a complete sentence; specify base cases, transitions, evaluation order, and where the answer is stored. A recurrence needs both completeness and a reason it does not accidentally count solutions multiple times. Memoization explores reachable states recursively; bottom-up evaluation follows dependency order explicitly. Reconstruction stores a chosen transition or derives one afterward from the optimal values.

Worked example / reasoning

With coins 1 and 2 and target 3, ordered sequences are 111, 12, and 21, while unordered multisets are only {1,1,1} and {1,2}. Amount-first and coin-first loops model different counting problems. In minimization DP, unreachable states need an infinity sentinel whose arithmetic is guarded.

Learning sequence

  1. Draw the dependency graph of a small recurrence.
  2. Compare a recursive exhaustive solver, memoization, and iteration on the same inputs.
  3. Recover one optimal solution and verify its cost and legality independently.

P13 · Graph and tree foundations

Prerequisites: P02,P09.

Learn: Adjacency lists; BFS/DFS; grid flood fill; components; unweighted shortest paths; parent/depth; bipartiteness; forest versus tree.

Mastery check: Recover a BFS path and traverse a disconnected graph in O(n+m).

Watch for: Deep recursive DFS overflow; forgetting disconnected components; marking BFS vertices too late.

Study: Breadth First Search; Depth First Search.

Understand the idea

Represent a graph according to its scale and operations. Adjacency lists support traversal in O(n+m), including disconnected components. BFS discovers vertices in layers and yields shortest paths when every edge has equal cost. DFS exposes recursive structure and supports component and cycle reasoning. A rooted tree adds parent, depth, and subtree relationships, but an arbitrary graph needs visited-state handling. Grids are graphs whose neighbors can be generated without storing all edges.

Worked example / reasoning

In a maze, mark a cell when it enters the BFS queue and store its predecessor and incoming move. When the destination is found, follow predecessors backward and reverse the moves. Marking only when removing from the queue can insert the same cell repeatedly. A disconnected graph needs a traversal start in each unvisited component.

Learning sequence

  1. Implement iterative DFS and BFS on a graph and a grid.
  2. Reconstruct a shortest path and verify that every consecutive pair is adjacent.
  3. Test isolated vertices, disconnected components, a single vertex, and a long chain.

P14 · Geometry and numerical basics

Prerequisites: P01,P08.

Learn: Coordinates and vectors; squared distance; dot/cross products; orientation; area; rounding and absolute/relative error; exact integer predicates.

Mastery check: Bound a cross product and distinguish boundary, collinear, and strictly interior cases.

Watch for: Floating equality; overflowing squared distance; unnecessary square roots in comparisons.

Study: Basic Geometry.

Understand the idea

Geometry becomes simpler when predicates are separated from measurements. Orientation, collinearity, and many intersection decisions can be computed exactly for integer coordinates using cross products. Dot products express projection and perpendicularity; squared distances avoid unnecessary square roots. Bound products before selecting integer types. Floating-point output needs a tolerance model that accounts for both small and large expected values, and numerical comparisons should reflect the scale of the quantities involved.

Worked example / reasoning

For A = (0,0), B = (3,0), C = (1,2), cross(B-A,C-A) = 6, so C is left of directed AB and the triangle has doubled area 6. The same computation distinguishes a boundary point when the result is zero; an additional bounding-box test determines whether it lies on the segment.

Learning sequence

  1. Implement a point type, dot product, cross product, and orientation.
  2. Derive the polygon shoelace sum using signed triangle areas.
  3. Test repeated points, collinear points, large coordinates, and answers close to zero.

P15 · Elementary games and probability

Prerequisites: P09,P11,P12.

Learn: Winning/losing states; small-state minimax; parity strategies; equally likely outcomes; binomial counting; expected value and indicators.

Mastery check: Compute small cases exhaustively, then prove the observed game pattern; define the probability sample space.

Watch for: Extrapolating a game pattern without proof; assuming events are independent; treating expectation as a most-likely outcome.

Study: Handbook, chapters 24-25.

Understand the idea

For a finite normal-play impartial game, a position is winning if it has a move to a losing position, and losing if every move reaches a winning one. This recurrence is a proof framework, not permission to extrapolate an unverified pattern. Probability begins by defining elementary outcomes and their weights. Expected value is a weighted average; indicator variables often simplify a total even when the indicators are dependent. Independence must be justified before multiplying probabilities.

Worked example / reasoning

If a player may remove one or two stones and taking the last wins, positions divisible by three are losing. Every other position can move to a multiple of three, and every move from a multiple of three leaves that set. For two fair dice, enumerate the 36 ordered outcomes rather than treating the eleven possible sums as equally likely.

Learning sequence

  1. Tabulate winning and losing states before attempting a pattern proof.
  2. Enumerate small probability spaces and compare with a counting formula.
  3. Compute an expected count by summing event indicators and explain why independence is unnecessary.

P16 · Preliminary contest integration

Prerequisites: P01-P15.

Learn: Read and triage a whole set; estimate implementation cost; construct counterexamples; debug with brute force; split work and maintain a submission log.

Mastery check: Complete at least three unseen timed sets, upsolve the reachable misses, and explain every wrong submission.

Watch for: Only solving tagged exercises; ignoring easy implementation problems while chasing one hard task.

Study: KACTL reference and testing guidance.

Understand the idea

Contest integration is a separate skill from recognizing tagged exercises. Read a complete set, summarize each statement, estimate solution and implementation confidence, and revisit estimates as new information arrives. Keep proof work, coding, testing, and submissions visible to teammates. A failed attempt should lead to a specific hypothesis and a counterexample, rather than an unstructured rewrite. During upsolving, record the first reasoning step you missed so that the lesson transfers to other problems.

Worked example / reasoning

For a constructive output, build a checker that validates constraints without reproducing the construction. For an optimization problem, compare your implementation with exhaustive search on hundreds of tiny random cases. Save the random seed and smallest failing input when they disagree; a reproducible failure is more useful than a passing sample.

Learning sequence

  1. Run one unseen timed set using the intended team workflow.
  2. For every wrong submission, write the violated invariant or misunderstood requirement.
  3. Re-solve a reachable missed problem later without looking at the editorial.
