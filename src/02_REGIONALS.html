R01 · Ordered structures and monotonic structures

Prerequisites: P04,P05,P07.

Learn: Heaps; balanced ordered sets; event sorting; nearest smaller/greater; monotonic stacks/deques; interval scheduling and sweep events.

Mastery check: Choose between heap, deque, and ordered set and prove an amortized bound.

Watch for: Removing equal values incorrectly; inconsistent endpoint ordering at simultaneous events.

Study: Minimum Stack / Minimum Queue; Handbook, chapters 8.

Understand the idea

Choose an ordered structure from the operations you need. A heap exposes only an extreme element; an ordered set supports predecessor and successor; a monotonic deque discards candidates that can never become optimal again. Monotonic stacks solve nearest-smaller or nearest-greater relationships through an explicit pop condition. In a sweep, convert intervals into events and decide how equal coordinates are processed. The proof often charges each insertion and removal once, yielding a linear bound after sorting.

Worked example / reasoning

For sliding-window minima, store indices in increasing value order. When a new value arrives, remove larger or equal values from the back because they expire earlier and are no better. Remove expired indices from the front. Each index enters and leaves once. Whether equality should be removed depends on whether you need just a minimum value or a particular witness.

Learning sequence

  1. Implement nearest smaller and sliding-window minimum with different equality policies.
  2. Compare heap, set, and deque solutions for their supported deletions.
  3. Test touching intervals and document whether endpoints are open or closed.

Watch, read, and go deeper

Heap and ordered-structure foundations; implement the monotonic deque from the invariant above as a separate exercise.

R02 · DP breadth: knapsack, sequences, grids, intervals

Prerequisites: P12,P13.

Learn: 0/1 and unbounded knapsack; value-indexed DP; LIS O(n log n); LCS/edit distance; interval DP; DAG DP; weighted interval scheduling.

Mastery check: Derive two state formulations for knapsack and choose from constraints; reconstruct an answer.

Watch for: Optimizing an incorrect recurrence; reusing a state in the same iteration; confusing LIS tails with the actual subsequence.

Study: Knapsack Problem; Longest increasing subsequence.

Understand the idea

DP breadth means learning to choose the dimension that stays small. Weight-indexed knapsack is unsuitable when capacity is huge but total value is small; value-indexed DP reverses the perspective. Sequence DP compares prefixes, while interval DP combines subintervals through a split or endpoint decision. DAG DP evaluates states in topological order. The O(n log n) LIS method stores minimum possible tail values for each length, which are summaries rather than an actual subsequence.

Worked example / reasoning

In 0/1 knapsack, descending capacity iteration prevents the current item from being reused. Ascending iteration permits repeated use and models unbounded knapsack. For weighted interval scheduling, sort by finishing time, locate the last compatible predecessor, and compare skipping an interval with taking its weight plus the predecessor optimum.

Learning sequence

  1. Solve one weight-indexed and one value-indexed knapsack instance.
  2. Derive edit distance and an interval recurrence with explicit empty intervals.
  3. Reconstruct an LIS using predecessor indices rather than printing the tails array.

Watch, read, and go deeper

Subset-sum/knapsack foundations, sequence, and interval recurrence design, with reconstruction and dependency reasoning.

R03 · Small exponential methods

Prerequisites: P09,P12.

Learn: Meet in the middle; bitmask DP; subset transitions; Hamiltonian path/TSP; assignment counting; distinguish O(2^n), O(n2^n), and O(3^n).

Mastery check: Choose a correct exponential method from n and account for transition cost and memory.

Watch for: Calling every subset algorithm O(2^n); forgetting that the last vertex is part of a TSP state.

Study: Enumerating submasks of a bitmask.

Understand the idea

Small exponential algorithms exploit a small number of decisions rather than small numerical values. Meet in the middle splits n items into halves, enumerates O(2^(n/2)) summaries per side, and combines them by sorting, hashing, or two pointers. Bitmask DP additionally stores a compact history such as visited vertices and the final vertex. Enumerating every submask of every mask costs O(3^n), which is substantially larger than one pass over all masks.

Worked example / reasoning

For n = 40 subset sum, enumerate about one million sums per half instead of one trillion full subsets. For Hamiltonian paths, dp[mask][v] counts or optimizes paths visiting exactly mask and ending at v. A transition adds an unvisited neighbor; the last vertex cannot be omitted because future edges depend on it.

Learning sequence

  1. Compute both time and memory for n = 20, 24, and 40.
  2. Implement meet-in-the-middle subset sum with duplicate sums handled correctly.
  3. Compare subset DP with permutation enumeration on tiny graphs.

Watch, read, and go deeper

Bitmask DP and meet in the middle; the handout offers broader exact exponential algorithm context.

R04 · Tree DP and rerooting

Prerequisites: P13,R02.

Learn: Subtree sizes; diameter; independent sets and matching; merge child states; rerooting via outside contributions and prefix/suffix merges.

Mastery check: Explain the meaning of a state on a directed edge and reroot without recomputing all subtrees.

Watch for: Double-counting the parent contribution; requiring modular division when an inverse may not exist.

Study: Handbook, chapters 14.

Understand the idea

Tree DP summarizes the interaction between a subtree and its parent. The state should expose only the information the parent needs, such as whether the root is selected or matched. Rerooting supplies the complementary contribution from outside each subtree so that every vertex can act as the root. Prefix/suffix merges avoid recomputing all siblings for every child. The merge operation and identity must be specified even when the implementation looks like a simple pair of traversals.

Worked example / reasoning

Let down[v] be the sum of distances from v to its subtree. After computing subtree sizes, reroot the total distance sum across edge v-u by ans[u] = ans[v] + n - 2*size[u]. Distances to size[u] vertices decrease by one; all remaining distances increase by one.

Learning sequence

  1. Derive take/skip states for a maximum independent set on a tree.
  2. Implement the distance-sum rerooting formula and verify it with BFS from every vertex.
  3. Generalize a child merge using prefix/suffix products without assuming division is available.

R05 · Binary lifting, Euler flattening, and LCA

Prerequisites: P13,R06.

Learn: Ancestor jumps; entry/exit times; subtree intervals; lowest common ancestor; distances; path differences; functional graph jumps.

Mastery check: Answer LCA/distance queries and translate a subtree into one interval; separate Euler walk RMQ from entry-order flattening.

Watch for: Mixing two different Euler-tour arrays; too few lifting levels; mishandling roots and nonexistent ancestors.

Study: Lowest Common Ancestor - Binary Lifting.

Understand the idea

Binary lifting precomputes 2^k-step ancestors or transitions, allowing large jumps by decomposing the distance into bits. Euler entry order flattens every rooted subtree into a contiguous interval. LCA combines ancestry tests or depth equalization with jumps to locate the deepest shared ancestor. Distance formulas then reduce path questions to depths and LCAs. Functional graphs support the same jump table even though their global structure includes cycles rather than tree roots.

Worked example / reasoning

With entry times tin and exclusive exit times tout, u belongs to v's subtree exactly when tin[v] <= tin[u] < tout[v]. In an unweighted tree, distance(u,v) = depth[u] + depth[v] - 2*depth[lca(u,v)]. For node and edge path-difference updates, derive the cancellation points separately; their formulas differ at the LCA.

Learning sequence

  1. Build jump tables with a clearly defined root sentinel.
  2. Flatten a tree and answer subtree sums using a range structure.
  3. Test ancestor-descendant queries, equal endpoints, and jumps longer than a tree depth.

Watch, read, and go deeper

R06 · Fenwick, segment trees, and sparse tables

Prerequisites: P06,P08.

Learn: Fenwick point-update/range-sum; segment tree associative merges; static idempotent RMQ; coordinate compression; order statistics.

Mastery check: Specify the merge identity and prove associativity; choose a sparse table only when its query rule applies.

Watch for: Using overlapping sparse-table blocks for sums; mixing update/query indexing conventions.

Study: Fenwick Tree; Segment Tree; Sparse Table.

Understand the idea

Range structures differ in the algebra they require and the updates they support. A Fenwick tree compactly decomposes prefixes and is especially convenient for additive counts and sums. A segment tree combines adjacent aggregates with an associative operation and an identity. A sparse table answers static idempotent queries by overlapping blocks; this overlap works for min or gcd but double-counts a sum. Coordinate compression connects large values to frequency-based range queries.

Worked example / reasoning

For segment minimum, merge is min and the identity is positive infinity. For a prefix-frequency tree, finding the k-th present value descends according to the count in the left half. This requires nonnegative frequencies so cumulative counts remain monotone. A Fenwick range-sum query subtracts two prefixes because addition has an inverse.

Learning sequence

  1. Implement point-update/range-query versions of Fenwick and segment trees.
  2. State the merge and identity for sum, minimum, and a custom aggregate.
  3. Use a sparse table only after proving that overlapping blocks are valid for the operation.

Watch, read, and go deeper

Fenwick trees, sparse tables, LCA, and underlying range operations; use the original Study reference for segment-tree implementation.

R07 · Lazy propagation and richer range queries

Prerequisites: R06.

Learn: Range add/assign; composition order; aggregate length; bracket merges; search inside segment trees.

Mastery check: Write down how a tag transforms a node and how new and old tags compose before coding.

Watch for: Assignment and addition do not commute; propagating tags without accounting for segment length.

Study: Segment Tree.

Understand the idea

Lazy propagation postpones updates while keeping each node's aggregate correct. Specify what a tag does to a segment and how a new tag composes with an older one. Composition order matters for assignment and affine updates. A sum aggregate needs segment length to apply a range addition. Richer merges may track several fields, such as bracket balance and unmatched endpoints. Searching within a tree additionally requires a predicate that allows entire segments to be skipped safely.

Worked example / reasoning

Represent an update as x -> a*x+b. Applying (a1,b1) and then (a2,b2) yields (a2*a1,a2*b1+b2). On a segment of length len, the sum becomes a*sum+b*len. This single model includes addition and assignment, with assignment represented by a = 0.

Learning sequence

  1. Write tag composition on paper before implementing push.
  2. Stress-test alternating assignment and addition against a plain array.
  3. Implement first position exceeding a threshold and explain why each skipped segment cannot contain an answer.

Watch, read, and go deeper

The Fibonacci Machine video is an augmented segment-tree application; first implement the basic tree from the original Study references, then derive lazy-tag algebra.

R08 · DSU and minimum spanning trees

Prerequisites: P04,P13.

Learn: Union by size and path compression; Kruskal/Prim; cycle and cut properties; offline reverse processing; MST edge replacement.

Mastery check: Explain the cut property and use DSU to distinguish redundant edges from connecting edges.

Watch for: Confusing connectivity with reachability in directed graphs; comparing an MST with shortest-path trees.

Study: Disjoint Set Union; Minimum Spanning Tree - Kruskal.

Understand the idea

Disjoint set union maintains a partition under merges. Union by size and path compression give near-constant amortized operations for standard connectivity queries. Kruskal processes edges in nondecreasing weight and accepts only those joining different components; Prim grows a connected tree through its cheapest outgoing edge. The cut property explains safe choices, while cycle reasoning explains replacements. Offline reversal turns some deletion sequences into insertions that ordinary DSU can handle.

Worked example / reasoning

An added non-tree edge creates one cycle in an MST. Removing a maximum-weight edge on that cycle gives the cheapest tree containing the added edge. For a disconnected graph, Kruskal returns a minimum spanning forest, so a program expecting one spanning tree must also check connectivity.

Learning sequence

  1. Implement DSU with component sizes and a component counter.
  2. Prove Kruskal's choice using a cut and compare its output weight with Prim.
  3. Process a deletion-only connectivity task backward, preserving the timing of answers.

Watch, read, and go deeper

Cut/cycle proofs and minimum-spanning-tree correctness.

R09 · Shortest paths and state expansion

Prerequisites: P13,R01.

Learn: Dijkstra; 0-1 BFS; Bellman-Ford; Floyd-Warshall; negative-cycle relevance; multilayer graphs; reconstructing paths.

Mastery check: Select the method from edge weights and constraints; model a limited-use action as extra state.

Watch for: Dijkstra with negative edges; reporting an irrelevant negative cycle; overflow when adding infinity.

Study: Dijkstra - finding shortest paths from given vertex; 0-1 BFS; Bellman-Ford - finding shortest paths with negative weights; Floyd-Warshall - finding all shortest paths.

Understand the idea

A shortest-path algorithm depends on edge weights and the meaning of a state. BFS handles equal weights, 0-1 BFS handles weights zero or one, and Dijkstra handles nonnegative weights. Bellman-Ford allows negative weights and detects reachable negative cycles; Floyd-Warshall supports dense all-pairs queries. State expansion incorporates a resource or mode into each vertex so that the next transition depends only on the current state. Count expanded vertices and edges before choosing an algorithm.

Worked example / reasoning

To allow one discounted edge, use states (v,unused) and (v,used). Ordinary edges preserve the layer; taking a discounted transition moves from unused to used. Dijkstra remains valid if all resulting costs are nonnegative. A priority queue may contain old distance entries, which should be skipped after a better distance is known.

Learning sequence

  1. Implement path reconstruction alongside distances.
  2. Choose the algorithm for equal, binary, nonnegative, and negative edge weights.
  3. Model a fuel, coupon, or parity constraint and verify the expanded-state transitions.

Watch, read, and go deeper

Algorithm selection by weight assumptions; extend the model with resource or mode states.

R10 · Directed structure, SCC, and 2-SAT

Prerequisites: P13,R09.

Learn: Topological sorting; DAG DP; SCC condensation; implication graphs; satisfiability and assignment extraction.

Mastery check: Turn a logical clause into two implications and explain why a variable and its negation cannot share an SCC.

Watch for: Wrong SCC topological order when constructing the assignment; confusing directed and undirected connectivity.

Study: Strongly Connected Components and Condensation Graph; 2-SAT.

Understand the idea

Directed cycles are local obstructions to topological ordering. DFS finishing order or indegree elimination orders a DAG, while strongly connected components contract arbitrary directed graphs into a DAG of mutually reachable groups. A 2-SAT clause becomes implications between literals; the instance is impossible exactly when a variable and its negation lie in the same SCC. Constructing an assignment requires respecting the component order used by the implementation, rather than copying an inequality from another convention.

Worked example / reasoning

The clause (x or y) creates implications not-x -> y and not-y -> x. After building both edges for every clause, SCCs detect contradictions. Separately, a longest-path DP on the condensation DAG can aggregate component weights, but the aggregation must match what the original problem permits inside a component.

Learning sequence

  1. Implement topological sort and explicitly report cycles.
  2. Compare SCC output with brute-force reachability on small directed graphs.
  3. Validate a 2-SAT assignment by evaluating every original clause.

R11 · Bridges, articulation points, and BCC

Prerequisites: P13,R08.

Learn: DFS discovery/low values; bridges; articulation roots; edge-biconnected compression; vertex-biconnected blocks and block-cut trees.

Mastery check: Handle disconnected multigraphs by edge ID; distinguish bridge trees from block-cut trees.

Watch for: Skipping every edge to the parent rather than only the parent edge; treating the DFS root like other vertices.

Study: Finding Bridges in O(N+M); Finding Articulation Points in O(N+M).

Understand the idea

Lowlink values summarize how far a DFS subtree can reach using tree edges followed by a back edge. In an undirected DFS tree, a child edge is a bridge when its subtree cannot reach the parent or an earlier ancestor. Articulation points require a separate root condition. Biconnected components use an edge stack and must be distinguished from bridge-connected components. Keep edge identifiers so parallel edges are handled correctly.

Worked example / reasoning

For DFS edge v-u, low[u] > tin[v] makes the edge a bridge. If two parallel edges join v and u, skipping every neighbor equal to the parent hides the second edge and can falsely report a bridge. Skip only the reverse copy of the DFS tree edge. For a non-root vertex, low[u] >= tin[v] identifies a separating child.

Learning sequence

  1. Compute bridges and compare with removing each edge followed by BFS.
  2. Test parallel edges, a cycle with a tail, and disconnected graphs.
  3. Build a bridge forest or block-cut tree and explain what each new node represents.

Watch, read, and go deeper

Lowlink invariants and biconnected decomposition; retain edge identifiers for multigraphs.

R12 · Euler trails and graph construction

Prerequisites: P10,P13.

Learn: Hierholzer; in/out-degree conditions; connectivity of used edges; directed versus undirected trails; de Bruijn construction.

Mastery check: Output a trail and verify that every edge appears exactly once.

Watch for: Checking degree parity but not connectivity; deleting both directions inconsistently.

Study: Eulerian Path.

Understand the idea

An Euler trail uses every edge exactly once, whereas a Hamiltonian path visits every vertex. Hierholzer's algorithm follows unused edges and splices closed walks through a stack. Degree conditions are necessary but must be combined with connectivity of the vertices incident to edges. Directed and undirected versions have different degree equations. Edge IDs prevent using an undirected edge twice, and the final number of traversed edges is a useful validity check.

Worked example / reasoning

An undirected graph with exactly two odd-degree vertices can have an open Euler trail starting at one and ending at the other, provided all nonisolated vertices lie in one connected component. For a directed open trail, the start has outdegree-indegree = 1, the end has -1, and all others have zero.

Learning sequence

  1. Implement an iterative edge-ID-based Hierholzer traversal.
  2. Reject disconnected nonempty edge components even when degrees look correct.
  3. Model a de Bruijn sequence using length-(k-1) strings as vertices and length-k strings as edges.

R13 · Bipartite matching and max flow

Prerequisites: P13,R09.

Learn: Augmenting paths; Kuhn and Hopcroft-Karp; residual networks; Dinic; min-cut; edge-disjoint paths; vertex splitting; Konig's theorem.

Mastery check: Build a network with a clear interpretation for every capacity and recover the requested combinatorial object.

Watch for: Wrong reverse-edge indices; confusing edge-disjoint with vertex-disjoint paths; forgetting capacity sums can exceed 32 bits.

Study: Kuhn's Algorithm - Maximum Bipartite Matching; Maximum flow - Dinic's algorithm.

Understand the idea

Matching and flow solve allocation problems through local improvements in a residual graph. An augmenting path can undo previous choices, which is why it succeeds where a one-pass greedy assignment fails. Bipartite matching can use Kuhn or Hopcroft-Karp; general capacities motivate a flow algorithm such as Dinic. A minimum cut certifies the maximum flow value. Vertex splitting models vertex capacities, and unit capacities often model edge-disjoint routes.

Worked example / reasoning

In bipartite matching, an alternating path may replace one current match and create another, increasing the total by one. After a maximum matching, start from unmatched left vertices and traverse unmatched left-to-right and matched right-to-left edges. The unreachable left vertices together with reachable right vertices form a minimum vertex cover.

Learning sequence

  1. Implement residual reverse edges and test cancellation paths.
  2. Write a matching reduction with a meaning for every source, sink, and capacity.
  3. Verify both a feasible solution and a cut or cover certificate of equal value.

R14 · Modular combinatorics and recurrences

Prerequisites: P11,P12.

Learn: Factorials/inverses; binomial coefficients; stars and bars; inclusion-exclusion; extended GCD; CRT including noncoprime moduli; matrix exponentiation.

Mastery check: State inverse/CRT compatibility conditions and express a recurrence as a matrix transition.

Watch for: Using Fermat inverses with a composite modulus; dividing a modular exponent incorrectly; matrix order errors.

Study: Chinese Remainder Theorem; Binomial Coefficients; Binary Exponentiation.

Understand the idea

Modular combinatorics combines counting arguments with arithmetic assumptions. Factorials and inverse factorials make repeated binomial queries cheap when the modulus and range support inverses. Stars and bars counts nonnegative allocations; inclusion-exclusion corrects overlapping forbidden conditions. Extended Euclid finds Bezout coefficients and modular inverses when gcd is one. CRT combines compatible congruences, including noncoprime moduli. Matrix exponentiation speeds fixed-dimensional linear recurrences but does not make a large state space small.

Worked example / reasoning

The system x = 1 mod 4 and x = 3 mod 6 is compatible because the residues agree modulo gcd(4,6) = 2; its solutions are x = 9 mod 12. Changing the second residue to 2 makes the system inconsistent. For binomial coefficients modulo a prime p, the usual inverse-factorial formula fails once the factorial includes p.

Learning sequence

  1. Derive one counting formula before writing modular code.
  2. Implement noncoprime CRT with an inconsistency result.
  3. Construct a transition matrix from a recurrence and verify the first several terms directly.

R15 · String matching, hashing, and tries

Prerequisites: P03,P05.

Learn: Prefix function/KMP; Z-function; borders and periods; Rabin-Karp; polynomial hashes and collision risk; ordinary and binary tries.

Mastery check: Give deterministic KMP/Z solutions for exact matching and explain the probabilistic guarantee of hashing.

Watch for: Assigning dictionary map exercises to rolling hash; comparing unnormalized substring hashes; confusing trie edges with suffix links.

Study: Prefix function - Knuth-Morris-Pratt; Z-function; String Hashing.

Understand the idea

String matching replaces repeated character comparisons with reusable prefix information. The prefix function records the longest proper border of each prefix; KMP follows those borders after a mismatch. The Z-function measures agreement with the whole string from every starting position. Tries store shared prefixes explicitly, while binary tries support bitwise decisions. Polynomial hashing summarizes substrings probabilistically and requires a collision strategy; a hash table and a rolling string hash solve different problems.

Worked example / reasoning

For pattern abab, the prefix-function values are [0,0,1,2]. After matching abab and seeing a mismatch, a border tells KMP how much matched work remains useful. For substring hashes, normalize positions or compare using aligned powers; equal hashes are evidence under a probabilistic model, not a deterministic equality proof.

Learning sequence

  1. Implement prefix and Z functions and compare matches with direct scanning.
  2. Insert words into a trie while retaining terminal multiplicities.
  3. Document hash modulus, base choice, normalization, and collision handling for many comparisons.

R16 · Planar geometry and sweep lines

Prerequisites: P14,R01.

Learn: Segment intersection; polygon area and point inclusion; convex hull; polar-angle order; rotating calipers; closest pair; coordinate transforms.

Mastery check: Handle duplicate points, collinear hull points, and boundary cases explicitly.

Watch for: Sorting by an inconsistent floating angle comparator; assuming a polygon is convex without proof.

Study: Convex hull construction; Finding the nearest pair of points.

Understand the idea

Planar geometry combines exact predicates with global ordering. Segment intersection needs orientation tests plus explicit collinear overlap handling. A convex hull removes points that cannot lie on the boundary; the choice to retain collinear boundary points changes the pop condition. Sweeps turn geometry into changing one-dimensional order, with careful treatment of simultaneous events. Rotating calipers uses monotone movement around convex polygons, while closest-pair divide-and-conquer requires a packing argument to bound comparisons.

Worked example / reasoning

To test whether two closed segments intersect, handle strict crossings by opposite orientation signs, then handle zero cross products by bounding-box membership. Two collinear disjoint segments must not be accepted merely because all four cross products vanish. For polygon area, retain signed doubled area until the final conversion.

Learning sequence

  1. Implement intersection, point-on-segment, hull, and polygon area with shared predicates.
  2. Specify boundary behavior for point-in-polygon queries.
  3. Test repeated points, vertical segments, collinear hulls, and simultaneous sweep events.

R17 · Offline queries and square-root decomposition

Prerequisites: P06,R06.

Learn: Block decomposition; offline sweeps; Mo's algorithm and add/remove contributions; choosing block sizes; query reordering.

Mastery check: Derive an incremental statistic and explain why the query order changes runtime but not answers.

Watch for: Applying offline reordering to answer-dependent queries; claiming Mo is always faster than a Fenwick sweep.

Study: Sqrt Decomposition.

Understand the idea

Offline processing changes query order to reuse work. A sweep sorts events by one coordinate and maintains a structure over another. Square-root decomposition groups indices or values into blocks so an operation handles full blocks cheaply and boundary elements directly. Mo's algorithm orders interval queries to reduce total endpoint movement, provided the answer can be updated when one element enters or leaves. Select a block size from the actual operation costs and query count rather than assuming sqrt(n) is always best.

Worked example / reasoning

For the number of equal pairs in a window, adding a value of current frequency f creates f new pairs, then increments its count. Removing a value first decrements its count and subtracts the new frequency. This supports Mo's algorithm, while simply recomputing every answer would lose the benefit of query reordering.

Learning sequence

  1. Implement a block range-sum structure and count boundary work.
  2. Derive add/remove formulas for a nontrivial window statistic.
  3. Restore original query order and compare all answers with a quadratic baseline.

R18 · Numerical search and linear algebra introduction

Prerequisites: P08,P14,R14.

Learn: Unimodality; ternary/golden-section search; numerical bisection; vectors, rank and linear systems; Gaussian elimination with pivoting; exact versus floating fields.

Mastery check: Justify unimodality and implement elimination that distinguishes no solution, one solution, and free variables.

Watch for: Ternary search on a merely monotone or multimodal objective; using floating elimination for exact modular algebra.

Study: Ternary Search; Gauss & System of Linear Equations.

Understand the idea

Numerical search requires a structural property of the objective. Bisection needs a monotone sign or feasibility boundary; ternary search needs unimodality, with separate treatment for discrete endpoints. Gaussian elimination solves linear systems by row operations and exposes rank, inconsistency, and free variables. Floating arithmetic needs pivoting and scale-aware tolerance; finite-field elimination requires invertible nonzero pivots. A single returned vector does not establish uniqueness.

Worked example / reasoning

The equations x+y = 2 and 2x+2y = 4 describe infinitely many solutions, whereas replacing the second right-hand side by 5 creates inconsistency. In floating elimination, selecting a large available pivot reduces amplification of rounding error. Over a prime field, normalize using a modular inverse; over a composite modulus, that inverse may not exist.

Learning sequence

  1. Implement elimination returning no solution, unique solution, or free variables.
  2. Compare a ternary search with exhaustive evaluation on small discrete domains.
  3. Check a computed solution by substituting it into the original equations.

R19 · Regional games and probability

Prerequisites: P15,R02,R14.

Learn: Nim; mex and Sprague-Grundy; disjoint impartial games; probability DP; linearity of expectation.

Mastery check: Explain when XOR of Grundy values applies and solve an expectation problem with indicators.

Watch for: Applying Sprague-Grundy to partisan games or cyclic infinite play without additional analysis.

Study: Sprague-Grundy theorem. Nim.

Understand the idea

Sprague-Grundy theory compresses finite impartial normal-play games into nimbers. A state's value is the mex of its successor values; independent subgames combine by XOR. The theorem requires genuine independence of legal moves and a terminating game graph. Probability DP instead propagates probability mass or conditions expected values on the next transition. Linearity of expectation can avoid storing the full distribution when only an average is needed.

Worked example / reasoning

Two independent Nim heaps of sizes 3 and 5 have nim-sum 6, so the position is winning. A move reducing the second heap to 3 leaves XOR zero. If a move changes both components or their legal moves depend on shared resources, blindly XORing separately computed values is unjustified.

Learning sequence

  1. Compute Grundy values for a subtraction game and verify small disjoint sums.
  2. Derive a probability DP whose total mass remains one.
  3. Solve an expectation problem with indicators and compare against exact enumeration for tiny inputs.

R20 · Regional contest integration

Prerequisites: P16,R01-R19.

Learn: Model unfamiliar statements; combine two standard tools; test reference code; estimate team opportunity costs; prepare a permitted reference document.

Mastery check: Review six full regional sets, preserving at least three as unseen virtual contests; independently re-solve recurring failure types.

Watch for: Treating completion of an algorithm list as proof of contest readiness.

Study: KACTL reference and testing guidance.

Understand the idea

Regional readiness depends on combining familiar tools under an unfamiliar statement. Translate the story into objects, legal operations, an objective, and constraints before naming algorithms. Keep a tested reference library, but also know its indexing, numeric assumptions, and failure modes. During a team contest, implementation time and shared-computer access affect which problem should be attempted next. Post-contest analysis should separate modeling failures from proof gaps, coding errors, and poor allocation of effort.

Worked example / reasoning

An interval connectivity problem may become a sorted sweep with DSU; a path-counting problem may become SCC contraction followed by DAG DP. State why each transformation preserves the original answer. A correct standard routine does not rescue a reduction that permits illegal objects or loses relevant constraints.

Learning sequence

  1. Run a complete regional set with a shared submission and ownership log.
  2. Audit every library routine used against a small independent reference.
  3. Write one complete reduction proof for a missed problem before reading implementation details.
